# 技术设计：ChatGPT 订阅绑定与默认模型管理

## 核心原则

- 插件**只管理两件事**：ChatGPT 订阅的官方 OAuth 绑定/令牌看护，以及 `openai-codex` 模型路由与默认模型切换。
- 插件**不管理联网搜索**：搜索商（`searchProvider`）由用户在自己的 DSH profile 配置层自行指定；插件从不读取、改写或切换任何搜索配置。
- ChatGPT 订阅 OAuth 只证明 ChatGPT/Codex 模型线路，不证明可调用 OpenAI API 搜索、视觉、图片或其他工具。插件不把订阅 token 当 API key，不伪造能力。

## 状态模型

- 绑定成功：注册自有 `openai-codex` 路由（不覆盖用户同名自定义路由），把默认模型切换到 ChatGPT 模型，记录绑定前的默认模型。
- 解绑或令牌失效：清理插件自有凭据与路由，把默认模型恢复到绑定前的选择。
- 搜索配置完全独立于本插件：绑定/解绑/模式切换都不会触碰 `web-search-deepseek`、`web-search-exa` 等搜索设置。

## 切换触发

1. ChatGPT OAuth 绑定成功：注册自有 `openai-codex` 路由，保存并切换默认模型。
2. ChatGPT 解绑或令牌失效：清理凭据与路由，恢复绑定前默认模型。
3. 用户在模型切换器自行选择模型：DSH 原生能力，插件不干预。

## 能力边界

- 插件不把订阅 token 当搜索或任何其他 API 的凭据。
- 插件不读取、删除或记录任何搜索密钥（`DEEPSEEK_API_KEY`、`EXA_API_KEY` 等）的值。
- 搜索是否可用、用哪家搜索商，完全取决于用户在 DSH 的搜索配置，与本插件无关。

## 验证

- 静态测试验证绑定状态机、凭据生命周期、用户配置保护、重复绑定/解绑与异常回滚。
- 构建后验证 `lib/` 与 `src/` 一致。
- 独立 QA 验证绑定/解绑矩阵；独立安全审计扫描凭据、个人路径、依赖和 OWASP 风险。
